# 开发计划

## 设计原则

以 Windows 布局为起点：左侧分类树、中间搜索与表情网格、右侧属性面板。
提供可调整分栏、右键菜单、多选、键盘导航和悬停操作。
共享色彩、字体层级、图标、间距和标签组件；Android 后续采用触控布局。

## 阶段 0：工具链与桌面验证

已完成：项目 Wrapper、JBR 21 构建脚本、共享三栏空库界面、Windows 入口。
首次编译与独立应用目录打包已通过，并完成 5 秒启动存活检查。
尚未进行视觉验收、性能测量与 QQ/微信兼容性验证。

- 确认 JDK，选择相互兼容的稳定 Kotlin、Compose 与 Gradle 版本。
- 配置 Gradle Wrapper，构建最小 Windows 应用。
- 建立共享模块与桌面平台适配边界，Android 工程在桌面原型稳定后接入。
- 使用真实图片验证 PNG/JPEG/GIF/WebP 的预览与发送。
- 测量正式分发构建的包体、冷启动、快捷键呼出、窗口隐藏时资源占用。
- 用千张图库验证滚动和缓存，动图默认封面，按需播放。

## 阶段 1：本地表情库

当前已实现本地文件/目录导入、SHA-256 去重、SQLite 元数据、PNG/JPEG/GIF/WebP 静态缩略图、
标题与标签编辑、搜索、收藏、回收站与恢复，以及事务性本地变更日志。
已验证重启持久化、失败隔离、字节级原图保留、回收站恢复、事务回滚、透明 WebP 和多帧 GIF 原图保留。
角色、批量编辑和备份恢复尚未实现；动画播放与系统发送仍待后续接入。

- 文件与目录导入、内容哈希去重、缩略图生成。
- SQLite 元数据、标签、角色、收藏、搜索与批量编辑。
- 原图不修改，发送转换文件与缩略图可重建。
- 原图、数据库与元数据的可校验备份和恢复。

## 阶段 2：同步闭环

- 定义带版本的数据协议与鉴权方式。
- 客户端离线操作队列、幂等提交、服务器增量游标。
- 内容哈希寻址图片、断点恢复、删除墓碑与回收站。
- 标签增删按操作处理，人工确认与 AI 结果分别记录。
- Android 优先同步元数据和缩略图，原图按需下载。

## 阶段 3：AI 整理

- PC 发起异步任务，可暂停、取消、重试，限制并发与预算。
- 识别文字、主体、情绪、动作、使用意图与角色候选。
- 动图按时间采样；角色允许未知，不强行命名。
- 保留模型和分析版本，重新分析不覆盖人工确认字段。
- 后续评估语义检索与角色参考图库。

## 开发约束

- 不以框架名称推断资源占用，使用正式构建与真实图库验证。
- 系统发送兼容性以真实目标应用验证结果为准。
- 同步冲突、重试与删除传播需要自动化测试。
- 不将第三方聊天缓存读取、社区、输入法或表情生成纳入首版。
